# 西电校园邮箱 App

一个把 https://mail.stu.xidian.edu.cn/coremail/ 打包成原生 Android 应用的小工具。
打开即用，不用再每次输入网址；保存学号和密码后可以**自动登录**。

## 安装 APK（手机）

1. 把 `西电校园邮箱-v1.4.apk`（或 `app/build/outputs/apk/debug/app-debug.apk`）传到手机上
   （微信/QQ 文件传输、网盘、数据线拷贝都可以）
2. 点击 APK 文件安装。从 v1.0 起的版本都是同一签名，覆盖升级直接安装即可，登录信息不会丢失
3. 如果被手机拦截，到 **设置 → 应用 → 特殊应用权限（或安全）→ 安装未知应用** 中允许文件管理器安装

## 使用

- 首次打开会进入登录页，登录一次即可
- 点右上角 **⋮ → 保存登录信息**，输入学号和密码
  - 密码使用手机系统级 **Android Keystore 加密存储**，不会明文保存在手机上
- 之后每次打开应用：
  - 如果会话没过期 → 直接进入邮箱
  - 如果会话过期 → 应用自动填写账号密码并点击登录，自动登录
- 菜单里还有：**刷新**、**用浏览器打开**、**清除登录信息**
- 网络异常（如 `ERR_NAME_NOT_RESOLVED`）时提示"网络不可用，恢复后将自动重试"，
  网络恢复后**自动重新加载页面并自动登录**，无需手动刷新

### 自动登录是怎么做的

登录页由 Coremail 的 JS 动态渲染，所以应用会在页面加载完成后轮询等待登录表单，然后：

1. 填写用户名 `#uid`
2. 填写**可见的**密码框 `#fakePassword`（页面提交时会用服务器公钥加密后写入内部隐藏字段）
3. 点击页面自己的「登录」按钮 `.j-submit`

为避免帮倒忙，以下情况应用**不会**自动提交，只提示手动登录：

- 出现图形验证码（`input[name=verifyCode]`）
- 出现二次验证 / 短信验证码
- 页面上已经显示了错误提示（如密码错误）

同一次运行中最多连续自动提交 **3 次**，两次之间至少间隔 **6 秒**，
避免密码错误时反复提交把账号锁掉。修改保存的密码后会重新计数。

## 更新日志

### v1.4
- 修复：**Android 16 上返回键失效**。targetSdk 36 时系统会忽略
  `android:enableOnBackInvokedCallback="false"`，`onBackPressed()` 不再被调用，
  导致在邮箱里按返回键直接退出应用。现改为注册系统 `OnBackInvokedCallback`
  （API 33+），旧系统仍走 `onBackPressed()`
- 修复：页面跳转/加载被新导航取代时，系统以 `ERR_ABORTED` 回调，被误判成"网络不可用"，
  不仅误弹提示，还会在下次网络变化时把正在看的页面整个重载
- 修复：渲染进程在应用处于后台时被回收，会立刻在后台重建 WebView 并重新加载页面；
  现改为回到前台后再恢复，避免后台反复拉起渲染进程
- 修复：Android 10+ 分区存储下，重复下载同名附件时 `File.exists()` 看不到已存在的文件，
  `DownloadManager` 直接失败；现在会换一个带时间戳的文件名自动重试
- 修复：设备上没有文件选择器时，网页的文件上传控件会一直卡住等待回调
- 新增：HTTPS 证书校验失败时明确提示（仍然取消请求，不会绕过证书校验）

### v1.3
- 修复：**自动登录从未真正生效**。旧代码按旧版页面结构查找 `#password`，但当前登录页的
  `#password` 是隐藏字段，可见密码框是 `#fakePassword`；同时 `#dologin/.btn-login` 等
  按钮选择器也匹配不到真实的 `.j-submit`，所以既没填对密码、也没点登录。
  现在按真实结构填写并提交
- 新增：自动登录保护——验证码 / 二次验证 / 已有错误提示时停止；最多 3 次、间隔 6 秒，
  避免错误密码反复提交导致账号被锁定
- 修复：WebView 渲染进程被系统回收（内存紧张、系统 WebView 更新）后白屏或整个应用闪退；
  现在会自动重建 WebView 并恢复原来页面
- 修复：附件下载不带 WebView 会话 Cookie，导致下载到登录页 / 401；同名文件导致下载直接失败；
  Android 8/9 下载到应用私有目录用户找不到
- 修复：多选文件上传时拿到 null（改用 `FileChooserParams.parseResult`）
- 旧版尝试用清单开关修复 Android 16 返回键，但该开关在 targetSdk 36 上被系统忽略，
  实际无效，已在 v1.4 用系统返回回调真正修复
- 修复：Keystore 加密失败时仍提示"已保存"
- 优化：`onPause` 时把 Cookie 落盘，减少"登录状态莫名丢失"；键盘弹出时调整布局；
  未知协议链接给出提示而不是错误页

### v1.2

## 开发者：在 Android Studio 中打开

用 Android Studio 打开本目录即可（Gradle wrapper 已配置，离线依赖已在本地缓存）。
若命令行构建提示找不到 SDK，新建 `local.properties` 写入 `sdk.dir=<你的 SDK 路径>`。

```bash
# 或者命令行构建（本机可用 JDK：C:\Users\SZZY\.jdks\temurin-24）
JAVA_HOME="C:\Users\SZZY\.jdks\temurin-24" .\gradlew.bat assembleDebug
# 输出: app/build/outputs/apk/debug/app-debug.apk
```

## 安全说明

- 密码加密密钥存放在手机 **Android Keystore** 中，即使手机被 root 也难以提取
- 如果不放心，使用后可以在菜单中**清除登录信息**，仅保留会话
- 校园邮箱会话过期后（通常几天），应用会自动重新登录
- 如果登录页出现验证码/滑块验证，请手动完成一次，之后会话会保持

## 已知限制

- 自动登录依赖 Coremail 登录页的结构（`#uid` / `#fakePassword` / `.j-submit`），
  学校改版后可能需要更新选择器
- 出现验证码或二次验证时无法自动登录（出于安全考虑，应用不会尝试绕过）
- 若学校开启了"新设备/异地登录验证"，仍需在手机上手动确认一次
- Android 16 起系统强制 edge-to-edge，v1.4 未调整窗口布局；若在你的机型上出现内容压到
  状态栏的情况，请反馈机型与截图
